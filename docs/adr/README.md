# Architecture Decision Records

Use one short ADR per important decision. Do not record assumptions as confirmed facts.

Suggested template:

```markdown
# ADR-NNN: Decision title

- Status: Proposed | Accepted | Superseded
- Date: YYYY-MM-DD

## Context
What problem or constraint requires a decision?

## Options considered
1. Option A
2. Option B

## Decision
What was selected and why?

## Consequences
Benefits, costs, risks, and future implications.

## Validation
How will the decision be tested or reviewed?
```

## Decisions to record

- Authentication integration and session/token strategy.
- File-storage provider and persistence approach.
- File type/size policy.
- Folder deletion and trash behavior.
- API contracts and error format.
- Indexing and pagination strategy.
- Any newly added dependency.
